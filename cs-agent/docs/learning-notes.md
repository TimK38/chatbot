## 二、觀念整理

### 1. Agent 的基本結構

- **Agent = 模型 + Harness（應用程式）**
  - 模型：負責思考、說話。它是**無狀態**的，每一輪都要把整段對話重新送進去。
  - Harness：負責跑迴圈、組裝提示詞、連接工具、做檢查。
- **核心迴圈（ReAct）**：

  ```
  while 還沒結束 且 沒超過最大輪數:
      把對話送給模型
      模型要用工具 → 執行工具 → 結果加回對話 → 繼續
      模型直接回答 → 結束
  ```

- **Harness 的五件事**：給上下文（Context）、給工具（Tools）、設限制（Constrain）、驗證（Verify）、修正（Correct）。

### 2. 上下文與成本

- **KV Cache**：模型把算過的「前段文字」暫存起來，下一輪前段一樣就不用重算，省時間也省錢。
- 所以上下文要**只增不改（append-only）**：固定的系統提示詞放最前面，新東西加在最後面。
- 上下文不是越多越好：塞太多，成本高，模型也會分心。

### 3. MCP（Model Context Protocol）

- **客戶端 / 伺服器**：Agent 的應用程式是客戶端，提供工具的程式是伺服器。
- **兩種連線方式**：
  - stdio：在本機啟動伺服器，用 stdin / stdout 對話。
  - Streamable HTTP：連到遠端伺服器。
- **訊息格式是 JSON-RPC**，主要流程：

  ```
  initialize（握手）→ tools/list（列工具）→ tools/call（呼叫工具）
  ```

- **握手的用途**：協商**協議版本**和**能力（capabilities）**。伺服器沒宣告的能力，客戶端就不會去用。
- **伺服器的名字有兩個**：
  - `serverInfo`：伺服器自己報的，只用來記錄和除錯。
  - `.mcp.json` 的 key：客戶端自己取的，Claude Code 用它組成工具名稱 `mcp__<key>__<工具名>`。由客戶端取名，可以避免撞名或被冒充。
- **伺服器提供的三種東西**：

  | | 誰決定用 | 用途 |
  |---|---|---|
  | 工具（tools） | **模型** | 查資料、做事情 |
  | 資源（resources） | **應用程式 / 使用者** | 提供參考資料 |
  | 提示範本（prompts） | **使用者** | 預先寫好的任務範本 |

- **資源的重點**：
  - 伺服器只負責**提供**，用不用、怎麼用，全部由客戶端決定。伺服器**無法強制**模型看任何東西。
  - 預設是一個都不載入。可以讓使用者挑（例如 Claude Code 的 `@`），或由開發者寫死載入少數幾個。
  - 啟動時載入的資源是**快照**，會過時；要最新資料就用工具。
  - 只對**信任的伺服器**寫死載入資源，否則等於讓惡意伺服器每次都能把注入文字放進系統提示詞。
- **工具標註（annotations）**：例如 `read_only_hint`、`destructive_hint`。它們只是**說明，不是鎖**。不信任的伺服器，標註不能當真。

### 4. Skills 與知識

- **Skills（流程）**：平常只把 name 和 description 放進提示詞，需要時才載入全文，這叫**漸進式揭露**。
- **知識（事實）**：用搜尋找出相關段落。
- **唯一事實來源**：同一個事實只放一個地方。例如價格只放在資料庫，知識文件不重複寫。

### 5. 安全

- **提示詞注入**：把資料偽裝成指令，騙模型照做。**間接注入**是把攻擊藏在工具回傳的資料裡（例如 C006 的備註）。
- **SQL 注入 vs 提示詞注入**：

  | | SQL 注入 | 提示詞注入 |
  |---|---|---|
  | 騙的對象 | 資料庫 | 模型 |
  | 防法 | `?` 佔位符，能完全擋住 | 沒有萬無一失的解法，只能多層防禦 |

- **致命三要素**：私密資料 + 不可信內容 + 能對外傳送。三者同時存在就很危險。
- **最小權限**：只給完成任務需要的權限。遠端伺服器的真正限制，是**你給它的鑰匙（token）權限**，不是它貼的標籤。
- **縱深防禦**：一道防線可能被突破，就疊好幾道。
- **提議者 / 審核者、Sidecar**：讓另一個角色在執行前審核，或執行後檢查。
- **沙盒 vs venv**：venv 只隔離套件版本，沙盒才隔離權限。

### 6. 評估（第 7 章，尚未細讀，以下是概要）

- **Pass@k**：試 k 次，至少成功一次。**Pass^k**：試 k 次，每次都成功。客服要看 Pass^k，因為要穩定。
- **一道題目的組成**（參考 τ²-bench）：客戶知道的資訊、客戶的劇本、初始資料、評分標準。
- **看行為紀錄，不看自我報告**：檢查資料庫和稽核紀錄，不相信 Agent 說「我做了 / 我沒做」。
- **題目要能重現**：每題都從乾淨的資料開始，日期寫死，否則分數會隨時間亂跳。
- 其他：資料洩漏（題目答案不能出現在 Agent 讀得到的地方）、LLM 評審、失敗歸因、回歸測試、統計顯著性。

## 三、MCP 伺服器實作：`server.py` 的六個區塊

檔案：[mcp_servers/starriver_db/server.py](../mcp_servers/starriver_db/server.py)

| 區塊 | 內容 | 學到的事 |
|---|---|---|
| ① 設定 | `MCPServer("starriver-db")`、`DB_PATH`、標籤 | `HERE` 讓路徑不受啟動位置影響；`STARRIVER_DB` 讓評估時能換成拋棄式副本 |
| ② 共用小工具 | `_db()`、`_log()`、`_not_found()`、`_system_date()` 等 | 沒有 `@server.tool` 就不會給模型看；底線只是給人看的提醒 |
| ③ 資源 | `starriver://plans` | 伺服器只提供，客戶端決定怎麼用 |
| ④ 唯讀工具 | `verify_identity`、`get_customer` 等 6 個 | docstring 就是給模型的提示詞；參數要夾住範圍 |
| ⑤ 寫入工具 | `change_plan`、`cancel_subscription` 等 4 個 | 目前刻意不檢查業務規則，讓評估能測出 Agent 有沒有守規則 |
| ⑥ 啟動 | `server.run()` | 用 stdin / stdout 對話，所以伺服器裡**不能 `print()`**，除錯訊息寫到 stderr 或 log 檔 |

### 重要細節

- **交易（全部成功，或全部不算）**：
  - `execute()` 只是寫進「草稿」，`commit()` 才真正存檔。
  - 同一條連線看得到自己的草稿，其他連線要等 commit 之後才看得到。
  - `_db()` 把 `commit()` 放在 `yield` 之後、`close()` 放在 `finally`：工具中途出錯，就跳過存檔，草稿全部丟掉。
- **錯誤要正常回傳，不要 raise**：回傳 `{"ok": False, "error": ...}`，模型才看得懂並修正，而且失敗紀錄才會被 commit 存下來。
- **稽核紀錄（`audit_log`）**：由伺服器在工具執行時自己寫，Agent 無法竄改，是評分的依據。
- **參數不能信任**：說明寫給模型看，限制要寫在程式裡。例如 `max(1, min(limit, 50))`。

### 貫穿整課的原則

> **真正的鎖，要放在模型碰不到的地方。**

- 提示詞規則（W1～W6）可以被注入攻擊繞過，因為它們只是「請模型遵守」。
- 工具 A 的結果交給工具 B 當參數，中間經過模型，可能被竄改，**不能當安全檢查**。
- 檢查放在伺服器（唯一的門）比放在每個 Agent 可靠，因為不需要靠每個人都記得。

**第 3 課目前學到的重點**
- 工具說明書（`SCHEMA`）= `name` + `description` + `parameters`（JSON Schema）。模型只看得到說明書，看不到 `run()`。
- `description` 就是提示詞：要寫「做什麼」，也要寫「什麼時候用、什麼情況改用別的工具」（例如「價格請用 list_plans」）。
- 內建工具用 `SCHEMA`，MCP 工具用 `to_openai()` 轉成同樣格式，模型分不出來源。工具清單每次呼叫都重送，且固定不變（KV Cache）。
- 模型要用工具時給的 `arguments` 是一段**字串**（模型寫出來的 JSON 文字），不是驗證過的資料。
- `run()` 的回傳值變成 `tool` 訊息，所以也能拿來指示模型。
- **誤解修正**：`SCHEMA` 只是說明，不是鎖，模型不一定照做，專案裡也沒有程式拿它檢查參數。傳 `{}` 時是 Python 的 `run(reason)` 因缺參數丟出 `TypeError`，不是 `SCHEMA` 擋下的。

- 第一道補充題（`{"reason": ""}`）：答對「`SCHEMA` 不擋」「檢查要寫在程式裡」。**誤解修正**：以為 Python 會因空字串出錯。其實型別標註 `reason: str` 也只是說明，執行時不檢查；Python 只會擋「參數名稱或個數不對」。內容檢查要自己寫（用 `.strip()`、`isinstance`，錯誤回傳 `{"ok": False}` 不要 raise）。

- 第二道補充題：`run(reason=["退款", ...])` 仍以為 Python 會擋（**型別標註誤解出現第二次**），實際執行示範後確認是正常執行。之後的課再留意這點。
- 重點表：`description`、`SCHEMA`、型別標註 `: str` 執行時都不檢查；Python 只擋參數名稱與個數；**只有真的會執行的程式碼才是鎖**。
