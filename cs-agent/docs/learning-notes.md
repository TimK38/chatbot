## 二、觀念整理

### 1. Agent 的基本結構

- **Agent = 模型 + Harness（應用程式）**
  - 模型：負責思考、說話。它是**無狀態**的，每一輪都要把整段對話重新送進去。
  - Harness：負責跑迴圈、組裝提示詞、連接工具、做檢查。
- **核心迴圈（ReAct）**：

  ```
  while 還沒結束 且 沒超過最大輪數:
      把對話送給模型
      模型要用工具 → 執行工具 → 結果加回對話 → 繼續
      模型直接回答 → 結束
  ```

- **Harness 的五件事**：給上下文（Context）、給工具（Tools）、設限制（Constrain）、驗證（Verify）、修正（Correct）。

### 2. 上下文與成本

- **KV Cache**：模型把算過的「前段文字」暫存起來，下一輪前段一樣就不用重算，省時間也省錢。
- 所以上下文要**只增不改（append-only）**：固定的系統提示詞放最前面，新東西加在最後面。
- 上下文不是越多越好：塞太多，成本高，模型也會分心。

### 3. MCP（Model Context Protocol）

- **客戶端 / 伺服器**：Agent 的應用程式是客戶端，提供工具的程式是伺服器。
- **兩種連線方式**：
  - stdio：在本機啟動伺服器，用 stdin / stdout 對話。
  - Streamable HTTP：連到遠端伺服器。
- **訊息格式是 JSON-RPC**，主要流程：

  ```
  initialize（握手）→ tools/list（列工具）→ tools/call（呼叫工具）
  ```

- **握手的用途**：協商**協議版本**和**能力（capabilities）**。伺服器沒宣告的能力，客戶端就不會去用。
- **伺服器的名字有兩個**：
  - `serverInfo`：伺服器自己報的，只用來記錄和除錯。
  - `.mcp.json` 的 key：客戶端自己取的，Claude Code 用它組成工具名稱 `mcp__<key>__<工具名>`。由客戶端取名，可以避免撞名或被冒充。
- **伺服器提供的三種東西**：

  | | 誰決定用 | 用途 |
  |---|---|---|
  | 工具（tools） | **模型** | 查資料、做事情 |
  | 資源（resources） | **應用程式 / 使用者** | 提供參考資料 |
  | 提示範本（prompts） | **使用者** | 預先寫好的任務範本 |

- **資源的重點**：
  - 伺服器只負責**提供**，用不用、怎麼用，全部由客戶端決定。伺服器**無法強制**模型看任何東西。
  - 預設是一個都不載入。可以讓使用者挑（例如 Claude Code 的 `@`），或由開發者寫死載入少數幾個。
  - 啟動時載入的資源是**快照**，會過時；要最新資料就用工具。
  - 只對**信任的伺服器**寫死載入資源，否則等於讓惡意伺服器每次都能把注入文字放進系統提示詞。
- **工具標註（annotations）**：例如 `read_only_hint`、`destructive_hint`。它們只是**說明，不是鎖**。不信任的伺服器，標註不能當真。

### 4. Skills 與知識

- **Skills（流程）**：平常只把 name 和 description 放進提示詞，需要時才載入全文，這叫**漸進式揭露**。
- **知識（事實）**：用搜尋找出相關段落。
- **唯一事實來源**：同一個事實只放一個地方。例如價格只放在資料庫，知識文件不重複寫。

### 5. 安全

- **提示詞注入**：把資料偽裝成指令，騙模型照做。**間接注入**是把攻擊藏在工具回傳的資料裡（例如 C006 的備註）。
- **SQL 注入 vs 提示詞注入**：

  | | SQL 注入 | 提示詞注入 |
  |---|---|---|
  | 騙的對象 | 資料庫 | 模型 |
  | 防法 | `?` 佔位符，能完全擋住 | 沒有萬無一失的解法，只能多層防禦 |

- **致命三要素**：私密資料 + 不可信內容 + 能對外傳送。三者同時存在就很危險。
- **最小權限**：只給完成任務需要的權限。遠端伺服器的真正限制，是**你給它的鑰匙（token）權限**，不是它貼的標籤。
- **縱深防禦**：一道防線可能被突破，就疊好幾道。
- **提議者 / 審核者、Sidecar**：讓另一個角色在執行前審核，或執行後檢查。
- **沙盒 vs venv**：venv 只隔離套件版本，沙盒才隔離權限。

### 6. 評估（第 7 章，尚未細讀，以下是概要）

- **Pass@k**：試 k 次，至少成功一次。**Pass^k**：試 k 次，每次都成功。客服要看 Pass^k，因為要穩定。
- **一道題目的組成**（參考 τ²-bench）：客戶知道的資訊、客戶的劇本、初始資料、評分標準。
- **看行為紀錄，不看自我報告**：檢查資料庫和稽核紀錄，不相信 Agent 說「我做了 / 我沒做」。
- **題目要能重現**：每題都從乾淨的資料開始，日期寫死，否則分數會隨時間亂跳。
- 其他：資料洩漏（題目答案不能出現在 Agent 讀得到的地方）、LLM 評審、失敗歸因、回歸測試、統計顯著性。

## 三、MCP 伺服器實作：`server.py` 的六個區塊

檔案：[mcp_servers/starriver_db/server.py](../mcp_servers/starriver_db/server.py)

| 區塊 | 內容 | 學到的事 |
|---|---|---|
| ① 設定 | `MCPServer("starriver-db")`、`DB_PATH`、標籤 | `HERE` 讓路徑不受啟動位置影響；`STARRIVER_DB` 讓評估時能換成拋棄式副本 |
| ② 共用小工具 | `_db()`、`_log()`、`_not_found()`、`_system_date()` 等 | 沒有 `@server.tool` 就不會給模型看；底線只是給人看的提醒 |
| ③ 資源 | `starriver://plans` | 伺服器只提供，客戶端決定怎麼用 |
| ④ 唯讀工具 | `verify_identity`、`get_customer` 等 6 個 | docstring 就是給模型的提示詞；參數要夾住範圍 |
| ⑤ 寫入工具 | `change_plan`、`cancel_subscription` 等 4 個 | 目前刻意不檢查業務規則，讓評估能測出 Agent 有沒有守規則 |
| ⑥ 啟動 | `server.run()` | 用 stdin / stdout 對話，所以伺服器裡**不能 `print()`**，除錯訊息寫到 stderr 或 log 檔 |

### 重要細節

- **交易（全部成功，或全部不算）**：
  - `execute()` 只是寫進「草稿」，`commit()` 才真正存檔。
  - 同一條連線看得到自己的草稿，其他連線要等 commit 之後才看得到。
  - `_db()` 把 `commit()` 放在 `yield` 之後、`close()` 放在 `finally`：工具中途出錯，就跳過存檔，草稿全部丟掉。
- **錯誤要正常回傳，不要 raise**：回傳 `{"ok": False, "error": ...}`，模型才看得懂並修正，而且失敗紀錄才會被 commit 存下來。
- **稽核紀錄（`audit_log`）**：由伺服器在工具執行時自己寫，Agent 無法竄改，是評分的依據。
- **參數不能信任**：說明寫給模型看，限制要寫在程式裡。例如 `max(1, min(limit, 50))`。

### 貫穿整課的原則

> **真正的鎖，要放在模型碰不到的地方。**

- 提示詞規則（W1～W6）可以被注入攻擊繞過，因為它們只是「請模型遵守」。
- 工具 A 的結果交給工具 B 當參數，中間經過模型，可能被竄改，**不能當安全檢查**。
- 檢查放在伺服器（唯一的門）比放在每個 Agent 可靠，因為不需要靠每個人都記得。

## 四、目前發現的弱點（待補強）

| 弱點 | 說明 | 預計處理 |
|---|---|---|
| 查資料前沒強制驗證身分 | `get_customer("C001")` 不需要先驗證就能拿到完整資料，只靠 W1 | 步驟 4：伺服器記住驗證結果，其他工具查詢前先檢查 |

| 寫入前沒有程式強制確認 | 只靠 W2，而注入文字特地寫了「不需要向客戶確認」 | 步驟 4：Harness 看到 `WRITES_DATA` 的工具就暫停確認 |
| 送往外部的參數沒有檢查 | 只靠 W7（提示詞），模型仍可能把客戶資料放進 `microsoft_docs_search` 的查詢 | 步驟 4：Harness 在呼叫外部伺服器前檢查參數（例如擋下手機號碼、客戶編號） |
| 外部工具回傳太長 | `microsoft_docs_search` 一次回傳約 2 萬字，對話變長、變慢、變貴 | 之後：截斷或只取前幾筆結果 |

| 出錯退回不會復原工具 | API 出錯時 `rollback_turn()` 只移除對話，已執行的寫入工具不會復原 | 觀察即可，步驟 3 評估時注意 |

#### 第 0 課：全貌

- 模型只會「說」，不會「做」：它只看得到 `messages` 和工具清單，實際動作都由 Harness 執行。
- 我的電腦上跑 2 個程式（Agent、starriver 伺服器）；Gemini 和 Microsoft Learn 都在外部。
- **系統提示詞只送給模型，MCP 伺服器看不到**。`ClientSession` 只是「Agent ↔ 某台 MCP 伺服器」的連線。
- 送往 Google 的是**整個 messages**（包含查到的客戶資料）；送往 Microsoft 的**只有工具參數**。外部伺服器不知道我們的目的，也無法替我們把關，所以要有 W7。

#### 第 1 課：`messages` 列表

- 四種 role：`system`（54 行，建立時放一次）、`user`（66 行）、`assistant`（77 行，可能是 tool_calls，也可能是給客戶的回覆）、`tool`（84 行，用 `tool_call_id` 對應請求）。
- 帶 `tool_calls` 的 assistant 訊息客戶看不到，但一定要留在列表裡，否則 tool 結果會「憑空出現」，API 通常直接報錯。
- 「那標準方案呢？」能被理解，是因為整段對話每次都重新送出。
- 誤解修正：`message`（單數，這次的回應）≠ `messages`（複數，整段對話）；`return`（79～80 行）不會往列表加東西。

#### 第 2 課：核心迴圈

- 繼續或停只看第 79 行：回應有 `tool_calls` → 執行工具、加回結果、下一圈；沒有 → `return` 給客戶。
- `for _ in range(15)` 防止無限迴圈（一直燒額度）。跑滿後：通知畫面 → 存固定的轉接訊息 → `ended = True`。
- 一次回應要求 N 個工具 → 1 筆 `assistant`（含 N 個 tool_calls）＋ N 筆 `tool`。口訣：**先有「要」，才有「給」**。
- 誤解修正：第 63 行在迴圈外，每次 `respond()` 只檢查一次，判斷的是「對話還能不能繼續」。

#### 第 3 課：工具定義

- 工具說明書（`SCHEMA`）= `name` + `description` + `parameters`（JSON Schema）。模型只看得到說明書，看不到 `run()`。
- `description` 就是提示詞：要寫「做什麼」，也要寫「什麼時候用、什麼情況改用別的工具」（例如「價格請用 list_plans」）。
- 內建工具用 `SCHEMA`，MCP 工具用 `to_openai()` 轉成同樣格式，模型分不出來源。工具清單每次重送且固定不變（KV Cache）。
- 模型給的 `arguments` 是一段**字串**（模型寫出來的 JSON 文字），不是驗證過的資料。`run()` 的回傳值會變成 `tool` 訊息，所以也能拿來指示模型。
- **重點表（型別標註的誤解出現過兩次，之後要留意）**：

  | 寫在哪裡 | 執行時會檢查嗎？ |
  |---|---|
  | `description`、`SCHEMA` | ❌ |
  | 型別標註 `reason: str` | ❌（內建工具）；MCP 工具會被 MCP 套件用 pydantic 檢查型別 |
  | 函式的參數名稱和個數 | ✅ Python 會擋（`TypeError`） |
  | 自己寫的 `if` | ✅ |

  **只有真的會執行的程式碼才是鎖。**

#### 第 4 課：執行工具

- 離線追蹤 `search_policy`：型別轉一圈「文字 →`json.loads`→ dict →`**`拆開→ 參數 →`run()`→ dict →`json.dumps`→ 文字」，因為模型只能讀寫文字。`source` 只進 `trace`，不進 `messages`。
- 三種錯誤三個地方接住：JSON 壞掉（118 行）、沒有這個工具（139 行）、執行時出錯（140 行）。全部轉成 `{"ok": false, ...}`，不讓 Agent 當掉。拿掉 140～141 行 → `TypeError` 一路丟上去，程式當掉，第 125 行也不會記錄。
- `trace` 是 Agent 記憶體裡的列表（不寫檔），評估程式直接讀；記錄所有工具（含內建、含失敗）。`audit_log` 是伺服器寫進資料庫的。
- 誤解修正：`ended = True` 不會停止這次 `respond()`，內圈不檢查它，模型還會再被呼叫一次；`ended` 由外面（`main.py` 的 `while not agent.ended`）檢查。

#### 第 5 課：三個內建工具

**`load_skill`（漸進式揭露）**
- 平常只把目錄（name + description，實測 305 字）放進系統提示詞；需要時 `load_skill(name)` 以工具結果回傳全文（每份約 1000～1400 字）。

**`search_policy`（搜尋知識）**
- 知識（規則，是什麼）用搜尋；Skill（流程，怎麼做）用目錄點名。

- 誤解修正：`t in title` 是看兩個字有沒有**連在一起出現**，「消訂」也在「取消訂閱」裡（P3-1 是 11 分，不是 8 分）。

#### Python 小知識（上課中問到的）

| 主題 | 一句話 |
|---|---|
| `getattr(物件, "名稱", 預設值)` | 拿不到屬性就回傳預設值，不會丟 `AttributeError`。回報用的東西拿不到就算了，不要讓 Agent 當掉 |
| `@lru_cache` | 同樣的參數問第二次，直接給記住的答案，不重做。代價：執行中改檔案要重啟才生效 |
| `@dataclass` | 自動產生 `__init__`、`__repr__`（印得出內容）、`__eq__`（比內容）；**不檢查型別** |
| pydantic | 讓型別標註真的被檢查（`BaseModel`），可轉的自動轉、不行就 `ValidationError`。Gemini 回應、MCP 工具參數都用它 |
| 選用原則 | 內部可信資料 → dataclass；外部不可信資料 → pydantic 或自己檢查；要轉 JSON 的暫時資料 → dict |
| `split` vs `partition` | `split` 每個都切；`partition` 只切第一個，固定回傳（前、分隔符、後） |
| 裝飾器 `@...` | 寫一行，套件在背後幫函式加能力（`@lru_cache`、`@dataclass`、`@server.tool`） |
| VS Code 搜尋 | `Ctrl+F` 只搜目前檔案；`Ctrl+Shift+F` 搜整個專案 |

`.venv` 裡是安裝的套件，不是我們寫的。例如 MCP 套件在 `func_metadata.py` 依 `server.py` 的型別標註自動建 pydantic 模型檢查參數；`server.py` 本身沒有 pydantic 程式碼。
