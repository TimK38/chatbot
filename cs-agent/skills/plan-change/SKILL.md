# 方案變更與方案建議流程

## 適用情境

- 客戶說「我要升級」「我想換便宜一點的」「換成 XX 方案」
- 客戶問「哪個方案適合我？」「我是不是買太貴了？」
- 客戶抱怨「常常顯示已達同時觀看上限」

## 會用到的工具

`verify_identity`、`get_customer`、`list_plans`、`get_viewing_activity`、`search_policy`、`change_plan`

## 步驟

1. **驗證身分**（作業規範 W1）。

2. **查詢目前狀態**：用 `get_customer` 取得 `plan_id`、`billing_cycle`、`status`。
   - 若 `status` 是 `paused`：依知識庫 **P2-6**，暫停期間不能變更方案，請改用 `pause-and-resume` 流程先恢復。

3. **查詢方案目錄**：用 `list_plans` 取得各方案的價格、裝置數、畫質與 `tier`。**價格與規格一律以這裡為準**，不要憑記憶。

4. **客戶詢問建議時**（只給建議，不主動變更）：
   - 用 `get_viewing_activity` 查看最近 30 天的使用狀況，對照 `list_plans`：

   | 觀察到的使用狀況 | 代表什麼 |
   |---|---|
   | `blocked_by_concurrent_limit` > 0 | 同時觀看的裝置數不夠用 |
   | `devices_used` 的數量 | 實際用了幾台裝置 |
   | `qualities_watched` 有 4K | 需要支援 4K 的方案 |
   | 只用 1 台裝置、只看 720p | 較低等級的方案可能就夠用 |

   - 向客戶說明「**根據哪些使用紀錄**」得出建議，讓客戶自己決定。
   - 客戶只是詢問、沒有明確要求變更 → **到此為止，不要呼叫 `change_plan`**。

5. **判斷升級或降級**：比較新舊方案的 `tier`。
   - 用 `search_policy` 查 **P2-1（升級）、P2-2（降級）**，依規則決定：
     - 能不能辦理（例如年繳的限制）
     - 生效時間：`effective` 要設 `immediate` 還是 `next_cycle`
   - 依規則不能辦理 → 說明原因與替代方案（例如續約時再換），不要執行。

6. **向客戶確認**（作業規範 W2），複述：
   - 從哪個方案換到哪個方案
   - 新方案的價格（來自 `list_plans`）
   - 什麼時候生效

7. **執行**：客戶明確同意後，呼叫 `change_plan`。

8. **回報結果**：說明新方案與生效時間。

## 常見錯誤

| 錯誤 | 正確做法 |
|---|---|
| 降級時用 `immediate` | 依 P2-2 判斷生效時間 |
| 客戶只問「哪個適合我」就直接變更 | 只給建議，等客戶明確要求並同意 |
| 建議時只看裝置數，忽略畫質 | 也要看 `qualities_watched`，看 4K 的客戶需要對應的方案 |
| 憑記憶報價 | 價格一律以 `list_plans` 為準 |
